## 4. 做法

单一脚本 `ai_knowledge_app/scripts/check-ledgers.mjs`（与既有 `check.mjs` / `audit-api.mjs` 同栈，
**不引依赖**）。三类对账：

| 代号 | 对什么 | 怎么对 |
|---|---|---|
| **L1** | **门禁号**（第 4 条） | 解析 `03-Sprint排期.md` 的各 `# Sprint n` 段里的 `\| Gx-n \| 判据文字 \|` 定义表 → 得到 `{号 → 判据文字}`；再扫各批计划 §6+7 表格里引用的 `Gx-n` → 同一号在两处的**判据文字**做词元重叠比对，**低于阈值就报「同名不同义」并把两处文字并排打出来** |
| **L2** | **计划索引**（第 1 条） | `plan/README.md` 里出现过的计划文件名集合 ↔ `ls plan/*.md` **减去例外清单**（`README.md` / `汇总*.md` / `优化/` / 模板）。**双向报**：索引里有而盘上没有（死链）· 盘上有而索引里没有（漏登） |
| **L3** | **批次账**（第 2/3/5 条） | `plan/汇总.md` §2 的批次名集合 ↔ `plan/*.md` 的文件名集合（同上减例外） |

### 步 1 · 退出码分档（承上一批的硬口径）

`0` 全部一致 · `1` 发现不一致 · **`2` 前置不满足**（`plan/` 不存在 / 排期文件里**一张门禁表都没解析到**
—— 后者是关键：**解析器自己坏了会「零不一致」而看起来全绿**，必须与「真的一致」分开）。

### 步 2 · 只报不改

**本项不写任何文件。** 判据用 `git status --short` 证实跑完前后**无差异**。
理由：自动改写台账**改错比不改更贵**（它会把错误**固化**进权威文档）。

### 步 3 · 认下「会误报」

中文判据文字短（「四类模型」「密钥不外泄」），词元重叠**必然有误报**。对策：
① **只报差异、不判对错**（报告输出「这两处文字对不上，请人看」）；
② 例外清单可显式登记（写进脚本顶部的常量，**加一行必须写原因**）；
③ 阈值取**宽松**（宁可多报几条让人扫一眼，也不要漏掉 `G6-12` 那一种）。

## 6. 不做 / 风险

- ❌ **不做自动改写**（步 2）。也**不做**「跑批时强制卡住」—— 它是**报告**，不是门禁闸；
  卡不卡由人决定。⚠️ 若将来要升级成硬闸，必须先解决误报（步 3）。
- ❌ **不回溯修正历史文档**（`M09-B` 的正文 / 已发出的速览·变更记录·交付台账）。
  错号在那里是**事实**，改掉会毁掉「当时确实这么记」这条证据。⇒ 本项**只报**，
  由人在**下一次回填**时一并订正 + 留一行说明。
- ⚠️ **本项不能替代「登记表已经很烂」这个判断** —— 它只能保证**烂了会被看见**，
  不能保证**不再烂**。真正的修法是「让新增一处不必手改 N 处」，那属结构性改动，
  与 `S4-D2` 的结论一致（本项目在这件事上已选择「登记表 + 机器检查」的折中）。
- ⚠️ **射程如实写明**：L1 只能对**排期里存在的**门禁号做比对。
  「某条门禁被挂到了**另一个 Sprint** 的号」这种错，如果两边文字都说得通，**抓不到**。
