| **清存量 ≠ 修根因**（S4-D2 定） | 只要还有**别的入口在造**，存量清零就只是快照（实测：清掉 3629 行孤儿登录日志 → `mvn test` 一轮又添 **91 行**）。报「已清干净」时必须同时说清**还有哪个入口在造**，否则那句话下次开工就是假的 | `S4-D2` §8 判据 9 · §3 #99 |
| **根因靠数据定，不靠「谁最可疑」定**（S4-D2 定） | `S4-D2` 开工时的根因假设（`purgeProbeUsers` 漏删登录日志）**被数据推翻** —— 真漏点在**后端 `@SpringBootTest` 用例**，而被怀疑的那个脚本里该前缀**一行都没有**。若照假设动手，会花 1.5 人天修一个从没漏过的地方，真漏点继续漏。**先查数据（备份 + 按前缀分组计数），再定根因** | `S4-D2` §8 末节 · §3.4 假设 5 |
| **「取一个数」的判据必须先量再定**（S4-E2 定 · **阈值/上限/窗口一律适用**） | `O2` §6 建议「页级阈值取 10 并**先跑样本**」，用户裁定照办 —— 探针实测 **10 会让 4 份正常文档里的 7 个页面误报**（封面页 10 字 / PPT 导出页 11 字 / 截图页 8 字，它们**都有文本层**）。最终口径改成**绝对零、没有任何阈值参数**。⚠️ 本仓已有两次教训：`S4-B` 的 W1' 是**事后**返工（4 个用例红了才发现），`S4-E2` 是**开工第一步**花 0.5 人天拦住的 —— **代价差一个数量级**。探针的产出常常不是"确认了那个数"，而是"**否掉了那个数**" | `S4-E2` §3.4 探针结论 · §8「最值钱的一件事」 · `ParsedDocument#pageStats` javadoc |
| **审计里的「系统动作」必须与「匿名访问」分开**（S4-E2 定） | 由 `AuditAspect` 判定：**有登录态** → 那个人；**有请求但没登录态** → `anonymous`/「匿名」（真的有人匿名为之）；**既无请求也无登录态** → `system`/「系统」（后台 worker）。⚠️ 三者合成两个的后果是**假记录** —— 审计页上「系统自动跑完的解析」与「某个没登录的人干的事」长得一模一样（`O6` 判据 4 点名的就是这条）。新增后台审计点时**不要**手工传 operator，让切面判 | `AuditAspect#build` · `AuditEvent.SYSTEM_OPERATOR` · `S4-E2` §9 |
| **异步链路要串起来，必须显式传播 `traceId`**（S4-E2 定） | `TraceContext` 的 javadoc 一直写着「异步任务在工作线程里重新 set」，而**实现里没有任何 `TaskDecorator`**，`ParseWorker` 的自建池也不传播 —— 这句承诺挂了很久没人发现，因为**默认行为看起来是对的**：`current()` 会现场生成新 id，每条日志都有 traceId，只是**提交与完成不是同一个**。凡新增线程池/异步入口，先问一句「traceId 跟过去了吗」 | `AsyncConfig#traceIdPropagating` · `ParseWorker#execute` 的 set/clear · `ClaimedJob.traceId` · `S4-E2` §8 判据 8 |
| **基线的度量必须"对它要抓的那个退化敏感"**（`S5-M07-B` 定） | `O5` §5 判据 2 自称"本方案最重要的验证项"，而按它做出来的基线**第一版抓不到它自己要抓的东西**：注入 `keepLineBreaks=false` 后 **17 个样本全绿**（`chars` 10583→10559，落在 ±2% 带内）。**判据写完必须证伪一次**，否则"有基线"这件事本身就是假象 |
| **要真外部副作用的用例必须打 tag 隔离，且隔离要实测**（`S5-M07-B` 定） | 评测（`T-711`）要真调嵌入模型，与 `mvn test`「全替身、无网络」的硬口径冲突 → `@Tag("eval")` + `pom.xml` 的 `excludedGroups=eval` + `eval` profile。⚠️ **隔离不是写在配置里就算数**：必须实测 `-Dtest=X` 不带 `-Peval` 时得到 `Tests run: 0` |
| **MySQL 的 `||` 是逻辑或，不是字符串拼接**（`S5-M07-B` 定） | 默认 `sql_mode` 下用它拼字符串会报 `22001 Truncated incorrect DOUBLE value`。要拼用 `CONCAT(...)`。⚠️ 附带一条：**迁移失败会在 `flyway_schema_history` 留 `success=0` 的行，必须先清掉才能重跑** |
| **「产物认识、归属维度不认识」有两个方向**（`S5-M07-B` 补 · 承 `#109`） | `#109` 是**后端**那一个（`sys_async_task.kb_id` 写 NULL）；本批逮到**测试**那一个：**Java 用例侧的探针残留没有统一登记**（`cleanProbeData` 各用例类自己写，漏一处无人发现），而 E2E 侧的 `probe-teardown` 覆盖不到它们 —— 实测 7 个 Milvus 分区 + 190 行孤儿分片 |
| **重启后端前先确认端口占用者**（`S5-M07-B` 定） | `TaskStop` 会杀掉 `spring-boot:run` 的 maven 进程，但**它 fork 出的 JVM 活着**并继续占着 8080 —— 新后端**因端口占用启动失败**，而 E2E 照样"跑得通"（打在**旧代码**上）。判别法：带 token 请求**只有新代码才有的接口**，返回「资源不存在」即为旧进程 |
| **审计 `target` 的 SpEL 有 `#result`**（S4-E2 定） | 参数里没有、只有返回值能带出来的东西（如 `upload` 内部生成的 `docId`）用它。⚠️ **异常路径上 `#result` 为 null**，求值失败会降级为「类名#方法名」（有 catch 兜底）—— 这是有意的取舍：宁可少一个精确的 target，也不能因为取不到而让业务报错 | `AuditAspect#resolveTarget` 的注释 · `S4-E2` §9-7 |
