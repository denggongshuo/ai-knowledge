### 3.1 S6 摸底：模型配置热更新（**给 S6 开工省一次摸查**）

**需求口径**（用户 2026-09-14 明确 + 《09》§1.8/§1.9 原文一致）：
> **嵌入模型不支持前端配置，只允许运维人员用后端 SQL 脚本修改，前端只读预览。**

> **2026-09-15 · B2 相关更新**：本批已在 `modelClientRegistry` 上接线两处（`KbService#embeddingInfo` /
> `#vlModelInfo` 被 `T-402`/`T-403`/`T-411` 三处消费，都走 registry），**S6 换 `ModelConfigSource`
> 实现为 DB 版后，这三处显示会自动跟着变，无需改动**。另：`vlModel.name` 的展示名问题（下表 W10）
> 与 `appliedAt`（W11）仍待 S6；本批未引入新的模型相关接口。

**现状（实测，非推断）**：

| 事实 | 证据 |
|---|---|
| 表已建但是空的 | `V1__init_skeleton_schema.sql:182` 建 `sys_model_config`（字段齐全：`model_type`/`base_url`/`api_key_cipher`/`model_name`/`is_default`/`billing_*`/`enabled`…）；真库 `select count(*)` = **0** |
| 后端零实现 | `controller/` 只有 Auth/Dept/Health/Kb/KbGrant/Permission/Role/User×2，**无模型配置控制器**；`sys_model_config` 全仓只出现在 V1 建表 + 两处 javadoc |
| 页面全落 mock | `ModelConfigView.vue` 的 10 个调用全打 `mock/index.ts:1233~1344`，刷新即回滚 |
| `.env` 是唯一真实来源 | `application.yml:176~192` 的 `app.model.{chat,embedding,rerank,vl}.*` ← `${CHAT_API_KEY:}` 等；`BootstrapModelConfigSource` 注释原话「引导配置来自进程启动时读入的 yml，运行期不会变；改了就必须重启」 |

**「`.env` 兜底」语义要等 S6 才成立** —— 现在是 `.env` = 唯一来源。V1 表注释已把兜底写好了：`api_key_cipher IS NULL` = 用环境变量同名配置。

**接口裁剪（重要，勿照抄《09》§1.14）**：整批 **10 个接口收敛为 9 个**，嵌入的"写"侧全部去掉：

| 动作 | 《09》原文 | 落地应为 |
|---|---|---|
| `POST /system/model/config` | `EMBEDDING 不可新增` | 改成 **`EMBEDDING` / `RERANK` / `VL` 三类都不可新增**（均全局单例，不可多条） |
| `POST /{id}/activate` | 通用"切换启用" | **`model_type = EMBEDDING` 一律拒绝**（哨兵错误码；前端也无入口） |
| `POST /change-embedding` | 🚩 高危，全库重建 | **删除** |
| `GET /embedding-impact` | 影响量预计算 | **保留，但语义改为"若运维改库会怎样"的事前预览** —— 非"我要换"，故**不涉密、前端可直接调用**（与 §1.9「必须把影响量摆在明面上」一致） |

**嵌入侧前端裁剪**：`ModelConfigView.vue:577` 的「更换嵌入模型」按钮、顶部 banner（`:417` 由 `pendingRebuild` 驱动，当前无任何写入点、恒 false）、`changeDialog`（`:928`，由按钮开）**全部删除**；保留只读卡 + 影响量 + 三行显式提示。`sysApi.changeEmbedding` 应一并删除以免留死接口。

**⚠️ 必须先解决的前置约束（否则"运维改 SQL"这条路走不通）**：

需求侧已在 **4 处**写明「系统启动时检测到服务端嵌入模型配置与库内索引不一致 → 顶部提示需重建索引」（`ModelConfigView.vue:419/574`、`09` §1.8 页头标签、§1.9）。这个比对**现在没有数据源**：

- 当前维度是**代码常量** `MilvusConstants.DIMENSION = 1024`（注释：「曾误配置为 1536，与 bge-m3 不符会导致入库直接失败」）。
- 所以比对退化成「**代码常量 vs 代码常量**」，永远一致，**banner 永远不亮** —— 运维照着这个数改了库，系统不会报警，检索静默失效。

→ **S6 必须新增一列持久化的"库内向量维度"**（如 `sys_kb_index_meta.milvus_dim`，重建索引时写入；或全局单例表）。取值应是**实际建 collection 时用的维度**，不是"配置里写的维度"。`MilvusConstants.DIMENSION` 降级为初始默认值。这是这批的头号交付物。

**其余缺口**：

| 缺口 | 备注 |
|---|---|
| DB 实现 `ModelConfigSource` | 标 `@Primary` 让 `BootstrapModelConfigSource` 让位。⚠️ **两份 javadoc 打架**：`ModelConfigSource` 写"用 `@ConditionalOnMissingBean`"，`BootstrapModelConfigSource` 明确写**不要用**（放 `@Component` 上会被提前求值跳过 Bean，项目已实测）。**以实测为准** |
| **`version` 必须来自 DB** | 热更新的命门。版本不随配置变 → 缓存 key 不变 → **页面显示"已切换"、实际仍打旧端点**，界面上看不出来的那种错 |
| 启用切换时调 invalidate | 嵌入/重排/VL 全局单例 → `invalidateAll(type)`；对话多条 → `invalidate(type, id)` |
| 启用门槛 | 需求硬口径：**必须先测连接通过才能启用**（`T-903`），改过 BaseURL/Key 后要重测 |
| 兜底口径不能丢 | `ModelClientRegistry` 刻意区分：来源**抛异常** → 用最近一次有效配置；来源**正常返回空** → **不兜底、显式报错**（代表配置被删） |
| 同一类型只有一条启用 | 需求要求**唯一索引**保证（应用层并发会出双启用） |
