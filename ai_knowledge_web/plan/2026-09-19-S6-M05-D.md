## 5. 依赖与工具决策

**默认不引**。本批要新增的能力只有一个：**感知哈希（pHash）**。

| 方案 | 做法 | 代价 | 结论 |
|---|---|---|---|
| **不引依赖（既有栈）** | JDK 自带 `ImageIO` 解码 + 缩放到 9×8 灰度 + 逐行比较相邻像素得 64 bit（**dHash**） | ≈40 行；`ImageIO` 不支持 WebP / TIFF 多页（本仓抽出的图是 **JPEG**，`V29` 起 `IMAGE_FORMAT_JPEG` 写死） | ✅ **推荐** |
| 候选：`imgscalr` / `Thumbnailator` | 现成的缩放 + 部分感知哈希 | 各 ≈100KB~300KB；只为一次缩放引一个库；且它们**不直接提供 pHash**，真正的哈希仍要自己写 | ✗ |
| 候选：OpenCV（`org.openpnp:opencv`） | 工业级 `img_hash` 模块 | ≈100MB 原生库，本仓是桌面开发 + Docker 中间件，**为一次 64 位哈希引原生依赖不成比例** | ✗ |

**推荐**：**不引依赖，手写 dHash**。

**理由**（按本仓「要引依赖必须证明既有栈做不到」的口径）：
① **既有栈做得到** —— `ImageIO` 解 JPEG 是 JDK 标准能力，dHash 只是"缩到 9×8 → 比相邻像素"，
没有算法难点；② **它是判定链的一环，不是产品能力** —— 判错的后果是"把某张图当装饰图"，
而这条链**已经被两道保守默认值守着**（阈值可配 + 只减不增）；
③ **`T-O03` 的正向证据本来就只能靠合成**（C2 §8.5 补探实测：三份真样本没有一份含跨页同位置的图）
⇒ 引一个 100MB 的原生库换不来更强的证据。

> ⚠️ **算法选 dHash 而不是 aHash/pHash 的理由**：dHash 对**亮度/缩放**敏感而对**压缩噪声**不敏感，
> 正合"同一张 logo 在文档里被重编码过"这个场景；且它**不需要 DCT**（pHash 要），40 行就能写完。
> ⚠️ **本批不承诺"dHash 是正解"** —— 它是**可替换的一环**（纯函数、单独可测），
> 若量出来不够用，换 pHash 只动那个函数。

### 212 专段：`T-O03` 的两个阻塞，以及"怎样才能做得到"

**阻塞 A —— `#205` 那条硬约束（先排除「≈整页」的盒子）做不了。**

`#205` 要求排除"≈整页"的盒子，但**产物里没有页面尺寸**：`ImageInfo.Box` 只有
图自己的 `[x0,y0,x1,y1]`，`PdfDocumentParser` 也不存任何页宽/页高。
判"这个盒子是不是整页"必须有分母。

- **可选路径**：① 把页面尺寸加进 `ParsedDocument`（解析器那一步拿得到，属新能力）；
  ② 换判据 —— 不用"占页面比例"，改用文档内**几何分布**（例如该盒子高度 ≥ 本文档所有图盒子的
  最大高度且出现在 ≥ 阈值比例的页上）。②不用改产物，但它是**推断**，需要探针先证伪。

**阻塞 B —— 跨文档判定需要模糊匹配，而 SQL 只能精确匹配。**

"同一张 logo 被重编码过"这件事，正是 dHash（而非 md5）存在的理由；
但判定要在**跨文档**做，而 SQL 只能按值相等 `group by`。
精确匹配的 dHash ≈ md5 —— **新列等于白加**，且会做出一条"看着实现了、却抓不住重编码 logo"的规则。

- **可选路径**：① **LSH 分带** —— 64 位哈希切 4×16 位，四条 SQL 前缀/子串匹配取并集当候选，
  再在 Java 侧对候选算 Hamming 距离。这是标准做法，且不需要新依赖（`image_phash` 是十六进制字符串，
  按 4 字符一段 `in (...)` 即可）；② 把候选集整批拉回 Java 比 —— 语料一大就是 O(n²)，不推荐。

**已经挖清、可直接复用的部分（别重挖）**：

- **落点**：`pHash` 在**解析期**算 —— 那一跳字节就在手上（`PdfDocumentParser.storeImage`），
  不必让 `DocumentCleaner` 去读 MinIO（**保住它的纯函数性**，见该类 javadoc）；
  判定在**落库后**做，**照 `T-O09` 步 3/4 的 `is_boilerplate` 同形**（`DocRecordWriter#markBoilerplate` 是模板）。
- **不要做单文档层的判定**：`#205` 的假阳性（`健康生活方式` 全扫描件上「同尺寸同位置」恒成立）
  **正是单文档层产生的**；而跨文档规则**天然不会**命中它（一份文档永远到不了 ≥N 篇）。
  ⇒ 本批把原计划的"分两层"收窄成**只做跨文档那一层**，既避开了 A 的大部分风险，也不丢最强的判据。
- **列**：`image_phash CHAR(16) NULL` + `is_decorative TINYINT(1) NOT NULL DEFAULT 0`
  + `KEY idx_chunk_iphash`。⚠️ **`TINYINT(1)` 不是裸 `TINYINT`** —— 后者 Hibernate 映射成 `byte`，
  `ddl-auto: validate` 会当场拒绝启动（本批实测踩到，修法是照 `V19` 的 `is_boilerplate` 写）。
  加列**必须同步 `SysChunk` 与 D-5 §1.1**，否则 `ChunkContractTest`（双向断言）转红 —— 本批已走过一遍。
