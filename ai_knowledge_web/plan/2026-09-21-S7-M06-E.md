### 3.2 业务流程图

打包下载：跨 ≥3 组件（Controller→Service→AsyncTask→MinIO→NoticePublisher）+ 异步任务 + 状态机（DownloadStatus）⇒ 必须画。

```mermaid
flowchart TD
  A["POST /doc/batch-download {docIds}"] --> B{"同步校验\n≤50件 且 ≤2GB\n每个 docId 可见?"}
  B -- 超限/越权 --> R["PARAM_INVALID\n现象 + 下一步"]
  B -- 通过 --> C["asyncTaskService.submit\ntype=batch-download\nTaskSubject(ownerId)"]
  C --> D["返回 {taskId, count, status=PENDING}"]
  C -.异步体.-> E["逐个 getObject 从 MinIO"]
  E --> F["ZipOutputStream 打包"]
  F --> G["putObject batch-download/{uid}/{stamp}.zip"]
  G --> H["presign GET 10min"]
  H --> I["每篇写 sys_download_record(BATCH)"]
  I --> J["context.complete(payload{fileUrl,expiresAt})"]
  J --> K["NoticePublisher.payloadOf\ncase batch-download → SYSTEM\n带「去下载」动作"]
  E -- 失败 --> X["markFailed → ALERT 通知 + errorMsg"]

  L["GET /doc/download-tasks/{taskId}"] --> M["AsyncTaskStatus → DownloadStatus\nPENDING/RUNNING→PACKING\nDONE→DONE FAILED→FAILED 过期→EXPIRED"]
```

单篇下载：

```mermaid

  C --> D["写 sys_download_record(SINGLE)"]
  D --> E["@AuditLog 下载文档 NORMAL"]
  E --> F["返回 {url, expiresAt, expiresInSec}"]
```

## 5. 依赖与工具决策

**默认不引**。

| 方案 | 做法 | 代价 | 结论 |
|---|---|---|---|
| 不引依赖（既有栈） | zip 用 JDK `java.util.zip.ZipOutputStream`；预签名用既有 `MinioClient#getPresignedObjectUrl`（`AuditExportService` 已用）；异步用 `AsyncTaskService`；通知用 `NoticePublisher` | 无 | ✅ **采用** |
| 候选：commons-compress | 支持 7z/tar/分卷 | +~1MB，且本批不需要分卷（§3.3 明确不做） | ✗ 不引 |

**推荐**：全部用既有栈 · **理由**：打包下载与审计导出（`AuditExportService`）在存储层面无差别 —— 异步任务 + MinIO + presign + 通知四件套已齐，zip 是 JDK 自带能力。引 commons-compress 只有在需要分卷/7z 时才值得，而那是明确不做的范围。

> 无新依赖（用既有 `java.util.zip` + `MinioClient` + `AsyncTaskService` + `NoticePublisher` 实现）。
