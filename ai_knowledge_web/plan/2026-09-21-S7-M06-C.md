### 3.3 明确不做（范围控制）

| 不做的事 | 原因 | 归属批次 |
|---|---|---|
| **不引 `markdown-it`**（需求 `07:317` 点名的"Markdown 增量渲染"） | 那是**渲染**口径，本批要的是**角标可溯源**。引入一个 markdown 解析器会把"正文渲染"整块拖进来（XSS 清洗、节流、增量），而当前是 `<pre>` 纯文本 —— **本批只把 `[n]` 变成可点角标**（正则替换），不动其余 | 前端小批（新登记） |
| **不做 `downVotes`**（`DocMeta` 的另一个恒 `null` 字段） | 它要的是**"这篇文档的答案被点踩几次"** —— 那是 `sys_chat_message.feedback` × `trace_id` × `doc_id` 的**跨表口径**，与 `citations`（引用计数）不是同一件事。混进本批会让"两个字段一起转真"看起来像同一条判据 | 新登记（`DocMeta` 的写侧） |
| **不加 `sys_chat_message.attachment_ids` 列** | 加列 = 新持久化产物（登记表 + 覆盖率闸 + 残留自检三处）。本批先如实登记"刷新后按钮消失"，等"轮次附件"这个口径在需求侧落笔 | 需求方确认后 |
| **不做「重新生成」** | 需求 `07:371` 点名的四件之一，与反馈同排一行但**不在** `T-804`/`T-806` 范围内（承 `#164`） | `T-807` 余下 |
| **不调 `max_tokens`**（应对 reasoning 吃光预算） | 阈值先量再定（`measure-before-picking-a-threshold`）—— 本批只**看 `finish_reason` 取证**，拿到数据再议 | 独立小批（若真发生） |
| **不动 `RetrievalScope` / 密级链路** | 上一批刚收口，本批不碰 | — |

### 3.4 本批假设

| # | 假设 | 若被证伪的后果 |
|---|---|---|
| 1 | **给 `CHAT` 那行把 `capabilities.vision` 置 `true` 是正当的** —— 步 0 探针实测**同一个模型**（`.env` 的 `CHAT_MODEL` = `deepseek-flash`）**确实看得懂图** | 若实际不支持 ⇒ `T-806` 交付了一个"按钮能点但一调用就报错"的功能。⚠️ 但**默认值仍是 `false`**（`ModelConfigDefaults.VISION`），本批只改**本机那一行数据**，不改默认值 ⇒ 影响面限于本机验证 |
| 2 | **原图走 base64 数据 URL**，不走预签名 URL | 预签名 URL 已实测 HTTP 400（relay 下载不了外网图）⇒ 这不是假设，是**已证事实**。真正的不确定性是**体积**：单张 ≤10MB 的图 base64 后 ≈13.3MB 的请求体，可能撞 relay 的请求体上限 ⇒ **失败现象是 HTTP 413/400，不是"答错"**，必须与"模型没看懂"分开报 |
| 3 | **`usedVision` 只做"本轮痕迹"**（不加 `attachment_ids` 列）⇒ 刷新后按钮消失 | 用户刷新页面后**看不到**「已读原图」标记与按钮 —— 而需求 `07:312` 要求消息页脚标注它。**这是本批最可能被需求方打回的一条**，故在第 9 节显式登记 |
| 4 | **角标解析只认 `[n]` 半角方括号** | 模型若输出 `【1】`（全角）或 `(1)` ⇒ 解析为空 ⇒ `cited` 全 0 ⇒ **`citations` 从恒 `null` 变成恒 `0`** —— 那比 `null` 更糟（`null` 是"没采集"，`0` 是一句关于内容的断言）。**处置**：解析为空时 `cited` 仍写 `null`（不是 0），并留 warn |
| 5 | 历史 `citations` 的 `index` 语义改成"角标号"**不破坏前端** | 前端 `ChatView.vue:351` 那个 `i+1` 会一并改掉；但**其它消费方**（若有）会看到 `index` 不再是检索名次 ⇒ 故**另加 `rankNo` 字段**，两个数都发，不替换 |
| 6 | 判据 14（代复核的证伪）**能在本批做完** | 它要构造"复核代与当前代不一致"的时点；若构造不出（同 `#210` 那样"机制有证据、复现不出"）⇒ 退化为"接线判据"并如实说明**没声称修好了竞态** |

## 5. 依赖与工具决策

**默认不引。**

| 方案 | 做法 | 代价 | 结论 |
|---|---|---|---|
| **不引依赖（既有栈）** | ① 角标解析：**手写正则** `\[(\d{1,3})\]` + 去重排序。形态是冻结的（我们自己写在 prompt 里），不需要完整 Markdown 语法 | 无。约 30 行 | ✅ **推荐** |
| 不引依赖（多模态） | Spring AI 2.0.1 **自带** `org.springframework.ai.content.Media` + `UserMessage.builder().media(...)` —— 与既有 `RegistryVisionCaller` 用的是**同一套**（那边已在跑） | 无 | ✅ **推荐** |
| 候选 A：引 `markdown-it` | 让正文按 Markdown 渲染 | 新增前端依赖 + XSS 清洗 + 增量节流；**且它解决的是另一个问题**（见 §3.3） | ❌ 不引（本批） |
| 候选 B：引 `commonmark-java`（后端解析角标） | 后端按 AST 取链接/文本节点 | 一个完整解析器只为找 `[n]`；且它会把"模型输出的是不是合法 Markdown"变成前置条件 | ❌ 不引 |

**推荐**：**无新依赖** —— 角标用手写正则，多模态用 Spring AI 既有 `Media`。
**理由**：角标的语法**由我们自己在 prompt 里定义**，是一个冻结的小语言；引入解析器等于为一个自己定义的语法引入通用解析能力。

## 10. 建议

1. **下一批 = S7 后片**（`G7-5`~`G7-14`：版本 / 下载 / 回收站，共 10 条门禁）。

   而后果（大图撞上限 vs 模型没看懂，现象相同）正是本仓反复吃的那类亏。

   超了直接 `sink.error("图片过大…")` —— **明确拒绝**比"发出去然后 4xx"好，因为后者与模型失败同形。

   （`HybridRetrievalFlowTest` 的收尾是完整的）。⇒ 照 `#190` 那条教训：**动一条遗留之前先核实它的前提还在不在**。
